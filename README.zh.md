# dsh-delete-chat

[English](README.md) | 中文

在 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)（DSH）里删除对话的一部分。

DSH 的会话日志是只追加的：已经写进去的事件不能原地擦除。这个插件在公开的
Session API 之上提供两种真正可行的删除方式，做法都是**新建一个会话**，只保留
你要留下的那部分；原会话保持不变（随后自动归档，可恢复）。

| 操作 | 结果 |
| --- | --- |
| **只删除这一轮，保留后面的对话** | 新会话保留被删轮次之前**和**之后的所有轮次 |
| **删除这一轮及之后的所有对话** | 新会话只保留被删轮次之前的部分 |

## 发错会话了？

这正是这个插件要解决的场景。

用「删除这一轮及之后的所有对话」从发错的那一轮切掉：新会话保留发错之前的全部
上下文，误发的消息以及它引出的后续内容不会再进入模型历史；原会话自动归档，
不会继续在后台影响你之后的对话。

如果发错的那一轮在中间、后面还有想保留的内容，用「只删除这一轮，保留后面的
对话」，插件会把前后两部分重新接起来。

## 安装

1. 克隆仓库：

   ```sh
   git clone https://github.com/yoyoluming1/dsh-delete-chat.git
   ```

2. 在 DSH 里打开 **插件 → 添加插件**，选择克隆下来的目录，然后点**立即启用**。
3. 打开或新建一个会话，至少发一条消息让某一轮完成。每一轮回复下方会出现
   **删除对话** 按钮。

更新插件源码后刷新页面即可；替换已安装的包可能需要重启一次 DSH。

### 看不到「删除对话」按钮

客户端模块是在页面加载时注册的。先刷新页面；如果启用插件后仍然没有按钮，
重启一次 DSH（会话日志不会丢）。

## 使用

把鼠标移到某一轮最后一条回复下方，点 **删除对话**，然后选：

- **只删除这一轮，保留后面的对话**：删掉这一轮，把后面的轮次带进新会话继续。
- **删除这一轮及之后的所有对话**：保留到这一轮之前，后面整段丢弃。

新会话会自动打开，原会话会被自动归档，列表里不会再出现两个同名会话。
需要对照或反悔时，到 **已归档** 里取消归档即可。

## 工作原理

插件在 Host 注册一个 `delete-chat` 命令，Chat 里每一轮的按钮通过
`ctx.remote.commands.execute` 调用它。Host 先算出要保留的事件，然后通过
**agent factory**（`ctx.agents.create`）创建新会话——和内置「在新对话中分支」
完全相同的事务：写入持久化、进入 SessionStore、广播、写投影缓存、准备一个
空闲 Agent 给下一条消息，并挂进原来的工作区。最后归档原会话。

- **删除这一轮及之后**：保留未改动的前缀，在切点处标记为继承分支，因此轮次
  编号和 delivery 标记都保持原样。
- **只删除这一轮**：重建事件并重新编号，重映射所有引用 seq 的字段
  （`surfaceOp`、`sourceEventSeqs`、`headerSeq`、压缩范围、标题引用、
  图片省略目标、命令引用）。

原始日志永远不会被修改，所以即使某次删除失败，也不会破坏源会话。

## 兼容性

在 DeepSeek Harness `0.2.2-rc.5`（Session 格式 v4）上测试。重建依赖 v4 事件
封套和持久化后端的严格读取器，如果 DSH 将来改动格式，插件可能需要跟进更新。

## 已知限制

- 只能按**整轮**删除，不支持删单条消息或单个工具调用。
- 「只删除这一轮」会**拒绝**被后续 `system/message` 替换或压缩事务引用的轮次
  ——强行丢弃会复活已被替换/压缩的历史；这种情况请改用「删除这一轮及之后」。
- 本身就是分支的会话（内置「分支」产生的，或上次截断产生的）可以继续**截断**，
  但不能在它上面做「只删除这一轮」：继承切点无法安全地带进重建后的日志。
- 新会话是新的 Session id，标题会按内置分支的约定加编号（`标题 (1)`）；原会话
  保留自己的 id、标题和日志。
- 截断产生的是一个 fork 会话（保留前缀被标记为继承）。它可以再次截断，但这条
  血脉上不能做中间删除。
- 中间删除后，后续轮次编号会前移一位（第 351 轮变成 350），这是磁盘格式要求。
- 截断会连同切点之后写入的记录一起删掉，包括最新标题、命令审计、后台任务
  记录和交付卡片。
- 会话还有未结束的轮次（正在运行）时会拒绝删除。
- 引用了被删消息的标题会随该消息一起丢弃。

## 发布

`scripts/publish.sh` 支持两种发布方式：

```sh
# SSH：先在 GitHub 建好空仓库，然后
GH_OWNER=you ./scripts/publish.sh

# Token：脚本会同时建仓库，并通过 HTTPS 推送
GH_OWNER=you GH_TOKEN=... ./scripts/publish.sh
```

token 模式只通过单次 HTTP header 传递 token，不会写进 `.git/config` 或仓库 URL。

## 开发

插件是纯 JavaScript：`index.js`（Host）和 `client.js`（浏览器模块）。

```sh
node test/remap-unit.test.mjs      # 轮次识别、splice 处理、删除范围
node test/client-module.test.mjs   # 客户端模块加载与 slot 注册
```

端到端回放测试跑在本机解码后的真实会话日志上，因为包含私人对话内容，所以没有发布。
